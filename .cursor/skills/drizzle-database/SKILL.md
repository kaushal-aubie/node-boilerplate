# Drizzle database (this project)

## Layout

- **Schema**: `src/db/schema/` — table definitions exported through `src/db/schema/index.ts`.
- **Migrations**: generated by Drizzle Kit; applied via **`pnpm db:migrate`** (`src/db/migrate.ts`).
- **Seed**: **`pnpm seed`** runs `src/db/seed.ts` (development data).

## Common commands

| Command | Use |
|--------|-----|
| `pnpm db:generate` | Generate SQL migrations from schema changes |
| `pnpm db:migrate` | Apply migrations |
| `pnpm db:push` | Push schema (dev; use migrations for anything shared) |
| `pnpm db:studio` | Open Drizzle Studio |

## Strict mode (required)

**`drizzle.config.ts` sets `strict: true`.** Keep it on. Drizzle Kit uses it to **prompt when a schema change is ambiguous** (notably **column renames**). With `strict: false`, the same diff can be generated as **drop column + add column**, which **destroys data** in production. If CI runs `drizzle-kit generate` non-interactively, ensure the process can surface prompts or pre-resolve renames (e.g. explicit `ALTER TABLE ... RENAME COLUMN` in a hand-written migration) so you never silently apply drop+add.

## Practices

- After changing schema files, run **`pnpm db:generate`**, review generated SQL, then **`pnpm db:migrate`** locally.
- Use **drizzle-zod** (`createInsertSchema`, etc.) in route files when request bodies should match table columns—see existing blog routes.
- Connection and pooling live under **`src/lib/infra/`**; env vars are loaded via **`src/config/env.ts`** / `env/.env.development`.
